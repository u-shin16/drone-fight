# Tello Connect

2台のTello EDUを、それぞれのPCからルーター経由で操作するローカル対戦アプリです。最初にドローン自身が飛んでミッションパッド1〜8の位置を測って地図を作り、対戦中はパッドで位置を補正します。

## 起動

各PCでPython 3.10以上を用意します。

```sh
python3 -m pip install -r requirements.txt
python3 app.py
```

表示された `http://127.0.0.1:5050` を開きます。ドローンと2台のPCを同じWi-Fiに接続し、それぞれのPCで自分の機体を選びます。初回にTelloのWi-Fiからルーターへ切り替える操作はアプリの「設定」画面で行います。

### 1台のPCで2台を動かす（1台モード）

PCが1台しかなくても、2台のTelloを戦わせられます。2台とも同じWi-Fi（ルーター）につないでおきます。

1. 「1. ドローンを探す」で、1台を「自分の機体にする」（A機）、もう1台を「B機にする」にします。
2. 「2. マッチング」の上で「1台のPCで2台を動かす」に切り替え、A機・B機のドローンを選んで「マッチング開始」。合言葉も相手のPCも要りません。
3. バトル画面の「A機の作戦／B機の作戦」で、それぞれの作戦を選びます。「準備OK」は1回だけで、5秒後に2台が同時に離陸します。
4. 勝ち負けは今までどおり（最後まで飛んでいた方が勝ち）。降参・緊急停止は2台とも止めます。地図（パッド）は1台のPCのものを2台で使い、相手の位置は同じアプリの中のもう1台から直接取ります。

Telloは最初に `command` を送ったPCにしか返事をしないので、2台とも同じPCがつかまえます。フィールドのスキャンは1台で行います。

## フィールドの種類（「フィールド」画面の上で切り替え）

- **パッドで正確に**：ミッションパッドの位置をドローンが飛んで測り（下の手順3）、対戦中もパッドで位置を直します。パッドは **4枚（正方形 `1 2 ／ 3 4`）か8枚（`1 2 3 ／ 4 5 6 ／ 7 8`）** から選びます。4枚の正方形はA機がパッド3、B機がパッド4から離陸し、パッド3が地図の原点です。8枚はA機がパッド4、B機がパッド6から離陸します。パッドの間隔や位置は自由で、スキャンが測ります。
- **パッドなし（予測）**：パッドを使いません。「2台の距離」「それぞれの後ろの余裕」「左右の余裕」を入れて保存するだけで、飛ばずに設定できます。A機とB機をその距離で向かい合わせに置き、相手の位置はお互いが送った移動命令から予想します（動くほどずれます）。

どちらの設定も、マッチした相手のPCへ自動で届き、両PCで一致するまで準備OKに進めません。

## 対戦の準備（パッドで正確に）

1. パッドを、奥から **「1 2 ／ 3 4」**（4枚）または **「1 2 3 ／ 4 5 6 ／ 7 8」**（8枚）の並びで、数字の面を上にして床に置きます。間隔や部屋の中の位置は自由です。ロケットの絵は全部同じ向き（4枚はパッド3から4の方へ、8枚はパッド4から6の方へ向く向き）にそろえ、スタートする2枚（4枚は3と4、8枚は4と6）は100cm以上離します。
2. 「1. ドローンを探す」で、各PCが自分の機体を「自分の機体にする」で選びます。
3. **（自動スキャンがうまくいかないとき）手動で飛ばしてスキャン**: 「フィールド」画面で枚数を選び、「手動で飛ばしてスキャン」を押すと、基準のパッド（4枚はパッド3、8枚はパッド4）から離陸します。矢印キー（または画面のボタン。地図の右がロケットの向き）で、30・50・100cmずつ動かします。ドローンは向きを変えずに平行に動き、パッドが見えると自動で位置を測ります。**全部のパッドの上を2回以上、別の方向から**通ったら「終わって戻る」を押すと、基準のパッドへ自動で戻って着陸し、地図を保存します（足りないうちは断られます）。飛べる範囲は、飛んだ場所とパッドの位置に60cmの余白を足して自動で決めます。基準のパッドから400cmより遠くへは行けません。停止（Esc）で着陸して、保存しません。
   **（または）手動で入力**: 「フィールド」画面の「手動で入力」で、基準のパッド（4枚はパッド3、8枚はパッド4）の中心を（0, 0）として、各パッドの中心までの距離（前後・奥手前、cm）と、飛べる範囲の4つの距離を自分で入れて保存します。ドローンは飛びません。保存後の地図は、スキャンで作った地図と同じように使われ、相手のPCにも届きます。
   **フィールドのスキャン（片方のPCで1回）**: 「フィールド」画面でパッドの枚数（4枚か8枚）を選び、スタートするパッド（4枚は3、8枚は4）から測って壁・人・家具にぶつからずに飛べる距離（後ろ・前・奥・手前、各50〜600cm）を入れ、自分の機体をそのパッドの中心にロケットの向きで置いて「スキャン開始」を押します。機体は高さ100cm・秒速60cmで、その長方形の内側（端から30cm）を、スタートの列から奥へ向かって往復しながら50cmごとに止まってパッドを読みます（見えない場所は0.25秒で次へ）。4枚の正方形は手前側にパッドがないので、手前は飛びません。全部のパッドが2回以上見えて位置が15cm以内にそろったら、すぐ終わってスタートしたパッドへ戻り、着陸します。保存するのは、全部のパッドが2回以上見え、同じパッドの位置が25cm以内でそろい、スタートしたパッドに戻ったときのズレが30cm以内で、番号の並びが正しいときだけです。どれかが満たせないとき、または停止ボタン（Esc）・状態の途切れ（1.5秒）・電池25%未満・向きのずれ20°超・移動命令の3連続失敗・時間切れ（範囲の広さに応じて最大6分）のときは、着陸して保存しません。開始には電池50%以上が必要です。写真は使いません。
4. 保存した地図はマッチした相手のPCへ自動で届きます。両方のPCに地図があるときは新しくスキャンした方にそろえます。両PCの地図が一致するまで「準備OK」に進めません。配置を変えたらスキャンし直します。
5. 「2. マッチング」で同じ4桁の合言葉を使い、バトル画面で作戦を選びます。A機はスタートパッド（4枚は3、8枚は4）の中心にロケットの向き、B機は4枚ならパッド4、8枚ならパッド6の中心に反対向きで置き、両PCで「準備OK」を押すと5秒後に離陸します。各機は開始パッドを確認してから動き、パッドが読めない・番号が違うときは着陸します。

バトル中の「降参」は着陸、「緊急停止」はプロペラ停止です。Esc・Ctrl+C・⌘Cでも降参できます。制限時間は60秒です。

## 位置と飛行範囲

地図のXはパッドのロケットの向き、Yはその右側です。パッドが見える間は状態パケットの `mid/x/y` で位置を補正します。見えない間は移動命令から予測するため、誤差は蓄積します。スキャンで指定した飛行範囲の外へ向かう命令は止めて着陸します。これは壁や人を検出する機能ではありません。

下向きカメラによるパッド検出の公式範囲は高さ0.3〜1.2mで、見える広さは高さ0.3mで40cm四方、1.2mで1m四方です。明るさ、床の色、機体の高さで検出できないことがあります。スキャンした地図の精度は、パッドとパッドの間を移動するときのTelloの移動誤差に左右されます。

## 検証と限界

- `python3 -m unittest discover -s tests` … 地図・スキャン（範囲、往復ルート、パッドの位置合わせ、保存しない条件）・安全の単体テスト。
- `tests/test_local_mode.py` … 1台モード（2台の開始・作戦・降参・緊急停止）を、ドローンに何も送らずに確かめるテストです。
- `python3 tests/scan_sim.py normal` … 偽のTelloでスキャンを最初から最後まで飛ばし、保存した地図と本当のパッド位置の差を表示します。`rough`（移動のズレ20%）、`missing7`（パッド7なし）、`state-drop`（状態の途切れ）、`stop`（途中で停止）、`start5`（パッド5から離陸）、`yaw`（向きのずれ）、`square4`（4枚の正方形）も選べます。
- `python3 tests/pad_battle.py 1_attack 2_flee 12 1 irregular` … 2台の偽Telloによる不規則配置の模擬戦です。パッドなしモードは `python3 tests/pad_battle.py 1_attack 2_flee 15 0 simple`。

偽Telloの結果は、偽Telloの動き方（移動のズレ、カメラの見える範囲＝高さ×約0.42の半径）を前提にしたもので、実機の精度や安全を保証しません。実機でのスキャン・飛行、2台同時の通信（1台モードで2台が同じPCに返事するか）、壁・人との離隔はまだ検証していません。

公式資料: [Ryze Mission Pad User Guide](https://dl-cdn.ryzerobotics.com/downloads/Tello/Tello%20Mission%20Pad%20User%20Guide.pdf)、[Tello SDK 2.0 User Guide](https://dl-cdn.ryzerobotics.com/downloads/Tello/Tello%20SDK%202.0%20User%20Guide.pdf)。

## 手動スキャンは、どこから・どの向きで離陸してもよい
手動スキャンは、パッドの上から離陸する必要がなく、機首の向きも自由です。離陸した場所を原点、機首を前として位置を記録し、パッドが見えたときのカメラの角度と、自分の移動のズレから「パッドの向きとのズレ」を割り出して、基準のパッドを原点・ロケットを右にした地図に直します。カメラの角度の符号は不明なので、両方を試して、自分の移動と合う方を採ります（`PadMap(free=True)`）。各パッドは、反対側から2回以上通ってください。`python3 tests/scan_sim.py angle`（55°向き）・`angle4`（-130°向き＋符号反転）で確認できます。

## 四角を自動で歩くスキャン（4枚）
どれか1枚のパッドの真ん中から、機首を隣のパッドの方（四角が右手に来る向き）に向けて離陸します。まっすぐゆっくり（秒速30cm・20cmずつ）進み、新しいパッドが見えたらその上を越えて真ん中へ戻って止まり、右へ曲がる、を4回くり返して最初のパッドへ戻ります。機体は実際には回らず、同じ辺を向きを変えずに進みます（回転の誤差を避けるため）。2辺目からは、直前に測った2枚のパッドを結ぶ向きで進むので、機首が少しずれていても影響は最初の1辺だけです。`python3 tests/scan_sim.py walk`・`walk4`（符号反転）・`walkrough`（移動誤差20%）で確認できます。

## 操縦（バトルと関係なく、選んだドローンを自分で飛ばす）
ナビの「操縦」ページ。`freefly.py`（友だちの pad_test.py をもとにしたもの）で、離陸→ホバリング→矢印キー/WASD（前後左右）、R/F（上下）、Q/E（回転）、Escで着陸。操作は1つずつ（動いている間は次を受けない）、4秒静かなら生存確認を送り（Telloは15秒で自動着陸するため）、電池12%未満・9分で自動着陸、緊急停止ボタンあり。下向きカメラのパッドの読みも表示します。バトル・スキャン中は使えず、操縦中はスキャン・準備OKを断ります。`python3 tests/fly_sim.py` で偽ドローンで確認できます。

## 緑を追いかける（操縦ページ）
友だちの attack-drn（https://github.com/jpsarchgac-blip/attack-drn ）の `tello_edu/battle/` と `config/battle_settings.yaml` をそのまま `tello_edu/`・`config/` に置くと、「操縦」ページに「緑を追いかける」「離陸して緑を追う」が使えます。他人のコード（ライセンス記載なし）なのでこのリポジトリには入れていません（.gitignore）。元の `EduDrone` は djitellopy で8889・8890番を自分で開いてこのアプリとぶつかるため、`tello_edu/session/edu_drone.py` だけ、開いているソケットとモニターを使う版に置きかえています。追跡中は安全制御（電池・高さ・傾きでの自動着陸）を設定ファイルの値で外してあり（元の値はコメントに残してあります）、やめると着陸します。`tests/test_chase.py` は合成画像で、緑に向かって前進・回って探す・着陸を確認します。

## カメラ映像（操縦ページ）
離陸すると前のカメラ（`streamon`）を映して、操縦ページの「カメラ」に出します（`camera.py`、MJPEG配信 `/api/fly/video`）。Telloが11111番に送るH.264映像を自分で受け取り（届いた個数を数えられる）、ffmpeg（`brew install ffmpeg`）でJPEGにします。ffmpegは `-fflags nobuffer` を付けると何も出てこなくなるので付けていません。画面の下の1行に、カメラの起動の返事・届いた映像データの個数・画像にできたコマ数が出ます。「緑を追いかける」の間は、追跡が緑に付けた枠つきの画像が映ります。`tests/test_camera.py` は、ffmpegで作った映像をUDPで流して画像になるところまで確認します。
